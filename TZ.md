# ТЗ: Omarchy Shutdown Timer — v2 «Aurora»

Полное техническое задание на переработку плагина `honor.shutdown-timer`
(bar-widget + overlay) в эталонный, публикуемый плагин Omarchy.

Статус: **черновик к реализации**. Автор: honor. Целевая версия: 2.0.0.

---

## 0. Как читать этот документ

Разделы 1–4 — зачем и для кого. Разделы 5–9 — что именно рисуем и как оно
себя ведёт. Разделы 10–14 — как это устроено внутри и как доказывается, что
работает. Раздел 15 — критерии приёмки: работа не считается сделанной, пока
не выполнен каждый пункт.

Правило приоритета: **надёжность отмены важнее красоты, красота важнее
фич**. Плагин, который выключил машину, когда пользователь жал «Отмена»,
провален независимо от того, как он выглядит.

---

## 1. Цель

Дать пользователю Omarchy единственный таймер питания, которым приятно и
не страшно пользоваться: поставить за две секунды, увидеть честный отсчёт,
отменить одним движением в любой момент — включая последние 30 секунд,
когда решение принимается.

Вторичная цель: сделать плагин настолько аккуратным и полным, чтобы он
стал **де-факто стандартом** для этого класса задач в Omarchy — первым,
что ставят из репозитория плагинов, и образцом качества для остальных
авторов.

## 2. Не-цели

- Не заменять системный `systemd-inhibit` и не бороться с ним.
- Не управлять питанием на уровне железа (яркость, лимиты заряда).
- Не быть планировщиком cron: расписания — только простые, недельные.
- Не поддерживать Windows/macOS-специфику.
- Не тянуть внешние зависимости сверх того, что есть в базовой Omarchy
  (`bash`, `jq`, `python3`, `omarchy-*`, Quickshell).

## 3. Пользователь и сценарии

Основной пользователь — владелец ноутбука или десктопа на Omarchy,
который ставит таймер в четырёх типичных ситуациях:

| # | Сценарий | Что важно |
|---|---|---|
| S1 | «Досмотрю фильм и спать» | поставить 45–120 мин, не отвлекаясь; отмена если заснул не сразу |
| S2 | «Качается торрент/сборка, потом выключить» | длинный таймер, индикация в баре, отсутствие лишних уведомлений |
| S3 | «Ребёнок/коллега за компом, выключить через 10 мин» | поставить быстро, показать крупно, отменить если передумали |
| S4 | «Забыл выключить — поставлю на 23:30» | абсолютное время, повтор по дням недели |

Ключевой вывод из S1 и S3: **отмена — не крайний случай, а штатная
операция**, и она должна быть доступна и на панели, и на экране отсчёта,
и с клавиатуры, и из CLI.

## 4. Принципы

1. **Отмена всегда ближе, чем подтверждение.** Ни один путь отмены не
   требует больше одного действия.
2. **Ничего не выключается молча.** Перед действием — окно отсчёта с
   крупным временем и явной кнопкой.
3. **Состояние переживает всё:** перезапуск shell, блокировку экрана,
   сон/пробуждение, перезагрузку сессии. Таймер не «теряется».
4. **Ноль фоновой нагрузки в покое.** В IDLE — ни одного пробуждения
   чаще, чем раз в 30 с.
5. **Тема — закон.** Ни одного хардкод-цвета; всё через `Commons.Color` и
   `Style`.
6. **Один плагин — один экран правды.** Никаких дублирующих демонов,
   никаких двух источников состояния.
7. **Всё, что видно, — проверяемо.** Каждый экран имеет автоматический
   тест и скриншот-эталон.

## 5. Информационная архитектура

Три поверхности, одна модель состояния.

```
Bar widget  ──ЛКМ──▶  Popup (постановка/управление)
     │                        │
     └──ПКМ──▶ быстрая отмена │
                              ▼
                        Overlay (последние N сек)
```

- **Bar widget** — иконка + остаток времени. Состояния: IDLE, ACTIVE,
  WARNING (≤5 мин), COUNTDOWN (≤30 с), PAUSED.
- **Popup** — постановка таймера, пресеты, действие, расписание, история.
- **Overlay** — полноэкранный отсчёт с отменой и «+5 минут».

## 6. Визуальный язык

### 6.1 Общие правила

- Только токены темы: `Commons.Color.foreground/background/accent/urgent/
  muted/popups.*`, `Style.space()/font.*/cornerRadius`.
- Никаких `#RRGGBB` в QML. Единственное исключение — `"transparent"`.
- Цифры таймера — строго моноширинный шрифт (`font.family: "monospace"`),
  чтобы разряды не дёргались.
- Анимации: 120–200 мс, `Easing.OutCubic`, только на `opacity`/`color`/
  `scale` (GPU-композитинг, без пересчёта лэйаута). Уважать
  «уменьшение движения» — при выключенных анимациях в системе всё
  мгновенно.
- Радиусы — `Style.cornerRadius`, отступы — только `Style.space(n)`.

### 6.2 Bar widget

- Иконка: **свой SVG-глиф** (см. 7), 1 цвет, `currentColor`-поведение через
  `foreground`.
- IDLE: только иконка, приглушённая до 0.55 — не отвлекает.
- ACTIVE: иконка + `MM:SS` (или `H:MM:SS` при ≥1 ч) моноширинным,
  `foreground`.
- WARNING (≤5 мин): цвет `accent`, иконка чуть ярче.
- COUNTDOWN (≤30 с): цвет `urgent`, иконка пульсирует `scale 1.0↔1.08`
  (600 мс, бесконечно, только в этом состоянии).
- PAUSED: иконка с точкой-индикатором, текст приглушён.
- Ширина меняется плавно (`Behavior on implicitWidth`, 160 мс), чтобы
  соседние виджеты не прыгали.
- Вертикальная панель: только иконка, время вертикально (`HH\n—\nmm`).

### 6.3 Popup

- Ширина `fittedContentWidth(Style.space(420))`, высота по контенту,
  максимум `Style.space(720)`.
- Секции: **Hero** (текущее состояние крупно) → **Пресеты** → **Точное
  время** → **Действие** → **Повтор** → **Дополнительно** → **История**.
- Hero в IDLE: «Таймер не задан» + подсказка «ЛКМ — поставить, ПКМ —
  отменить».
- Hero в ACTIVE: крупное моноширинное время, действие, кнопки
  «Отменить», «+5 мин», «Пауза».
- Пресеты: сетка 3×2 — 15, 30, 45, 60, 90, 120 мин. Каждая — `PanelActionButton`.
- Точное время: `PanelSlider` 1–1440 мин с шагом 5 + `NumberField` для
  ручного ввода; переключатель режима «через X мин / в ЧЧ:ММ».
- Действие: `Dropdown` — Выключить / Перезагрузить / Сон / Гибернация /
  Заблокировать.
- Повтор: «Однократно / Каждый день / Будни / Выходные / Выбрать дни».
- Дополнительно: «Не выключать на батарее», «Тихий режим (без
  уведомлений)», «Ждать завершения загрузок» (см. 9.4).
- История: последние 5 запусков — время, действие, чем закончилось
  (выполнено / отменено / отложено).
- Клавиатура: `j/k` — навигация, `Enter` — запуск, `Esc` — закрыть,
  `1`–`6` — пресеты.

### 6.4 Overlay

- Полноэкранный `PanelWindow`, `WlrLayer.Overlay`,
  `WlrKeyboardFocus.Exclusive`, `ExclusionMode.Ignore`.
- Фон: `background` с прозрачностью 0.92 + лёгкое размытие, если доступно.
- Центральная карточка `BorderSurface`: радиус `cornerRadius`, рамка
  `popups.border`.
- Содержимое сверху вниз: действие («Выключение»), крупное моношрифтовое
  время (`displayLarge`, при ≥100 с — `display`), прогресс-полоса
  убывания, кнопка «Отмена» (главная, рамка `foreground`), вторичная
  «+5 минут», подсказка «Esc — отменить, Enter — отложить».
- Цвет цифр: `urgent` в последние 10 с, иначе `foreground`.
- Последние 3 секунды: цифры пульсируют, тихий тик (если включён звук).
- Появление: fade 180 мс. Исчезновение: fade 120 мс.

## 7. Иконка

Собственный SVG `assets/timer.svg`, 24×24, `stroke` 1.75, `fill: none`,
скруглённые концы — в стиле Lucide/Phosphor, а не Nerd Font:

- Корпус: круг с разрывом сверху-справа (мотив «уходит время»).
- Внутри: две стрелки часов, одна короче.
- Снизу-справа: маленький символ питания, вписанный в разрыв круга —
  читается как «время → выключение» уже на 16 px.
- Отдельные варианты `timer-active.svg` (стрелки на 10:10, «идёт») и
  `timer-countdown.svg` (только питание + дуга) для смены состояния без
  пульсации.
- Обязательно: `currentColor`, оптическая центровка, проверка на 16/20/24
  px, отсутствие артефактов на тёмной и светлой теме.
- Глифы Nerd Font — только как fallback, если SVG не загрузился.

## 8. Состояния и переходы

```
IDLE ──set──▶ ACTIVE ──t≤warning──▶ WARNING ──t≤overlay──▶ COUNTDOWN ──t≤0──▶ FIRING
  ▲             │  ▲                   │                     │
  │             │  └──resume───────────┴──pause──▶ PAUSED   │
  └──cancel─────┴───────────────────────────────────────────┘
                                    └──snooze(+5м)──▶ ACTIVE
```

Правила:

- `set` в любом состоянии **перезаписывает** таймер (без диалога).
- `cancel` из COUNTDOWN закрывает overlay и возвращает IDLE.
- `pause` фиксирует остаток, `resume` продолжает с него.
- `snooze` из COUNTDOWN добавляет 5 мин и возвращает ACTIVE.
- FIRING: действие выполняется, состояние → IDLE, запись в историю.
- После сна/пробуждения: пересчёт по wall-clock; если время истекло во
  сне — окно отсчёта показывается сразу после пробуждения (не выключать
  в тёмный экран).

## 9. Функциональные требования

### 9.1 Постановка

- Пресеты, слайдер, ручной ввод, абсолютное время `ЧЧ:ММ` (с переносом на
  завтра, если время прошло).
- Валидация: 1–1440 мин; `ЧЧ:ММ` — 00:00–23:59; ошибка — инлайн-текст
  `urgent`, не тост.
- Действие по умолчанию — из настроек.

### 9.2 Отмена (критично)

Четыре независимых пути, все ведут к одному `cancel()`:

1. `Esc` на overlay.
2. Кнопка «Отмена» на overlay.
3. ПКМ по виджету в баре.
4. Кнопка «Отменить» в popup.

Требования:

- Отмена срабатывает и в последнюю секунду.
- Если `control.sh` недоступен, overlay пишет команду напрямую в файл
  управления (fallback уже реализован — сохранить).
- После отмены overlay закрывается **сам**, не дожидаясь действия.
- Отмена пишет запись в историю со статусом «отменено».

### 9.3 Отложить

- «+5 минут» на overlay и в popup; настраиваемый шаг (1/5/10/15).
- `Enter` на overlay = отложить.
- Отложить можно не более 3 раз подряд (защита от бесконечного
  откладывания), затем кнопка гаснет.

### 9.4 Условия выполнения

- «Не выключать на батарее»: при питании от батареи и заряде < порога
  (по умолчанию 20 %) действие `poweroff` заменяется на `suspend`, в
  overlay показывается причина.
- «Ждать завершения загрузок»: если активен `systemd-inhibit` с
  `what=sleep:shutdown` от другого процесса — ждать до 10 мин, показывая
  «Ждём: <причина>»; по истечении — действовать.
- Оба условия — опциональны, по умолчанию выключены.

### 9.5 Расписание

- Однократно / ежедневно / будни / выходные / набор дней.
- Хранится как `{"time":"23:30","days":[1,2,3,4,5],"action":"poweroff"}`.
- После срабатывания ежедневное расписание перевзводится на следующие
  сутки; в баре — иконка с точкой.

### 9.6 Уведомления

- За `notifyEarlyMins` (по умолчанию 5) — `normal`.
- В начале отсчёта — `critical` через `omarchy-notification-send`.
- Учитывать `dnd` в `~/.local/state/omarchy/notifications.json`; в popup
  показывать «уведомления заглушены».
- «Тихий режим» отключает оба.

### 9.7 CLI и IPC

`control.sh` — полный, документированный интерфейс (включая `override`
для сухого прогона — см. 9.9):

```
control.sh set <mins> [action]        control.sh cancel
control.sh at <HH:MM> [action]        control.sh pause | resume
control.sh snooze [mins]              control.sh status [--json]
control.sh schedule add <HH:MM> <days> <action>
control.sh schedule list | remove <id>
control.sh history [--json]
control.sh ensure | daemon-stop
```

IPC-таргеты: `honor.shutdown-timer` (виджет) и
`honor.shutdown-timer:overlay` (оверлей, `show/hide/cancel/snooze`).
Все методы возвращают строку-результат, пригодную для скриптов.

Хоткеи (документировать, но не назначать самовольно):
`omarchy-shell honor.shutdown-timer toggle`, `... cancel`.

### 9.8 Настройки (схема манифеста)

| ключ | тип | по умолчанию | смысл |
|---|---|---|---|
| `defaultAction` | enum | poweroff | действие по умолчанию |
| `overlaySeconds` | int 5–120 | 30 | длина окна отмены |
| `notifyEarlyMins` | int 0–60 | 5 | раннее предупреждение, 0 — выкл |
| `snoozeMins` | int 1–15 | 5 | шаг отложить |
| `presets` | string | `15,30,45,60,90,120` | список пресетов |
| `waitForInhibitors` | bool | false | ждать блокировки питания |
| `batteryGuard` | bool | false | не выключать на батарее |
| `batteryThreshold` | int 5–50 | 20 | порог заряда для guard |
| `quiet` | bool | false | без уведомлений |
| `tickSound` | bool | false | тик в последние 3 с |

### 9.9 Сухой прогон (не выключать ПК)

- Файл `<state>/action-override`: пока он непуст, демон вместо реальной
  команды запускает `<содержимое> <действие>` и пишет в журнал
  `executed via override: <команда>`.
- Переключается `control.sh override echo|off` и строкой «Сухой прогон» в
  разделе «Дополнительно»; в popup видно текущее значение.
- Отличается от `ACTION_OVERRIDE` (переменная окружения, читается на старте
  демона) тем, что читается **при каждом срабатывании** — E2E не требует
  перезапуска и не выключает машину.
- Обязательный тест: `tests/test_override.sh` (файл побеждает, env —
  фолбэк, снятие файла возвращает реальные действия).

## 10. Архитектура

### 10.1 Компоненты

```
manifest.json     kinds: bar-widget + overlay, схема настроек
Panel.qml         виджет + popup (только UI)
Overlay.qml       полноэкранный отсчёт (только UI)
Service.qml       мост UI ↔ демон, один экземпляр на shell
Model.js          чистое форматирование, без импортов
daemon.sh         единственный источник правды о времени
control.sh        CLI поверх файла команд
assets/*.svg      иконки
```

### 10.2 Источник правды

Только демон. UI никогда не считает время сам, кроме интерполяции между
опросами для плавности. Все записи состояния — атомарные:
`write_state` пишет во временный файл и делает `mv` (переименование в
пределах одной ФС атомарно).

### 10.3 Демон: без 1-секундного тика

Сейчас демон просыпается каждую секунду и на каждом тике запускает
`python3` несколько раз (`read_field`). Целевое поведение:

- Читать состояние **один раз** в начале итерации, разбор — на чистом
  bash (без `python3` в горячем пути).
- Спать не фиксированную секунду, а `min(до_следующего_события, 30)`:
  до смены секунды — только когда UI открыт, иначе до ближайшей границы
  (5 мин / 30 с / 0).
- В IDLE без расписания — `sleep 30` и проверка одного файла команд.
- Пробуждение по `inotifywait`, если он есть; иначе — короткий sleep
  только при активном таймере.
- Никаких дочерних процессов в покое.

### 10.4 Устойчивость

- Демон переживает перезапуск shell (запускается не из QML-жизненного
  цикла, а через `ensure` из `control.sh`).
- `trap` на `EXIT/TERM` пишет IDLE **только** если таймер не активен;
  иначе сохраняет состояние и восстанавливает при следующем старте.
- Один экземпляр: `flock` на pid-файл.
- При старте: если сохранён `targetTime` в прошлом — показать окно
  отсчёта с 30 с (не выключать мгновенно).
- Пересчёт по wall-clock, а не по счётчику — сон и перевод часов не
  ломают таймер.

## 11. Производительность (бюджет)

| Метрика | Бюджет |
|---|---|
| CPU демона в IDLE | ≤ 0.1 % |
| Пробуждений в IDLE | ≤ 2/мин |
| Дочерних процессов в IDLE | 0 |
| CPU демона в COUNTDOWN | ≤ 0.5 % |
| Память демона (RSS) | ≤ 6 МБ |
| Задержка реакции на отмену | ≤ 150 мс |
| Задержка отрисовки overlay | ≤ 250 мс |
| Файлов состояния | 1 (+ pid, + control) |

Проверка: `ps -o pcpu,rss`, `strace -c -f -p <pid>` за 60 с в IDLE,
`pidstat -w`. В отчёте — цифры, не «стало легче».

## 12. Доступность и локализация

- Все интерактивные элементы достижимы с клавиатуры, порядок логичный.
- Контраст текста ≥ 4.5:1 на фоне темы; проверить на светлой и тёмной.
- Не полагаться только на цвет: состояние дублируется текстом/иконкой.
- Строки — в одном месте (`Model.js`), готовность к переводу; сейчас
  русский + английские ключи.
- Уважать системный «уменьшить движение».

## 13. Тестирование

### 13.1 Обязательные автотесты (`tests/`)

1. `test_state.sh` — переходы состояний, перезапись, пауза, snooze-лимит.
2. `test_cancel.sh` — отмена из каждого состояния, включая последнюю
   секунду; проверка, что действие не выполнилось.
3. `test_absolute.sh` — `ЧЧ:ММ` в прошлом → завтра; ровно сейчас.
4. `test_schedule.sh` — перевзвод, дни недели, отмена.
5. `test_daemon.sh` — единственность (`flock`), восстановление после
   `kill -9`, отсутствие потери состояния.
6. `test_perf.sh` — бюджеты раздела 11, падает при превышении.
7. `test_override.sh` — сухой прогон (9.9): файл перебивает env, снятие
   файла возвращает реальные действия.
8. `test_sleep.sh` — дедлайн истёк во сне (SIGSTOP на 7 с): по пробуждении
   окно отсчёта, а не выстрел; окно дожимается до действия; живой таймер
   по-прежнему срабатывает без лишнего окна.

Все — без реального выключения: `ACTION_OVERRIDE=echo` в демоне.

### 13.2 Ручные проверки

- Реальный `Esc` через `wtype -k Escape` (единственное честное
  доказательство клавиатурного пути).
- Скриншоты каждого состояния на тёмной и светлой теме, до/после.
- Проверка на 16 px иконки, на вертикальной панели, на двух мониторах.
- Сон/пробуждение с активным таймером.
- Блокировка экрана во время отсчёта.

### 13.3 Что считается доказательством

Только: вывод команды, `state.json`, строка лога, скриншот с пиксельной
проверкой. «Компилируется без ошибок» — не доказательство работы.

## 15. Критерии приёмки

Работа принята, когда **все** пункты выполнены и подтверждены:

- [ ] Виджет виден в баре, занимает корректный слот, не прыгает.
- [ ] Иконка — собственный SVG, читается на 16 px, работает на обеих темах.
- [ ] Все пять состояний отрисованы и различимы без цвета.
- [ ] Отмена работает всеми четырьмя путями, включая последнюю секунду.
- [ ] Отмена закрывает overlay сама; ПК не выключается.
- [ ] «+5 минут» работает, лимит откладываний соблюдается.
- [ ] Пауза/возобновление сохраняют остаток.
- [ ] Абсолютное время и расписание работают, включая перенос на завтра.
- [ ] Состояние переживает `kill -9` демона и перезапуск shell.
- [ ] Сон/пробуждение не теряют и не «съедают» таймер молча.
- [ ] Бюджеты раздела 11 выполнены, цифры в отчёте.
- [ ] Все автотесты зелёные, `bash -n` чист на всех скриптах.
- [ ] Логи shell без `TypeError`/`ReferenceError`/`Unable to assign`.
- [ ] README, CHANGELOG, LICENSE, скриншоты готовы.
- [ ] Установка с нуля на чистой машине проходит по README.

## 17. Риски

| Риск | Смягчение |
|---|---|
| Отмена не дошла до демона | fallback прямой записью; проверка `state.json` после отмены |
| Демон убит системой | `flock` + восстановление из `targetTime` |
| Таймер «съеден» сном | пересчёт по wall-clock, окно отсчёта после пробуждения |
| Overlay не получил фокус клавиатуры | `WlrKeyboardFocus.Exclusive` + кнопка как основной путь |
| Плагин ломает чужой IPC | уникальные таргеты, `manageIpc: false` в виджете |
| Перегрузка при двух мониторах | один демон, один опрос, `notifyInstance` |
| Тема без нужных токенов | fallback на `foreground`/`accent`, проверка на 3 темах |
